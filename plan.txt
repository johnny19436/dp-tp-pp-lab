# Single-Node 2×A100 DP / TP / PP Experiment Plan

## Goal

I have one Vast.ai node with:

- 2 × NVIDIA A100-SXM4-40GB
- GPU0 ↔ GPU1 topology = NV12
- 40 GB VRAM per GPU
- single node only

The goal is to experimentally understand and compare:

1. Single-GPU baseline
2. Data Parallel (DP=2)
3. Tensor Parallel (TP=2)
4. Pipeline Parallel (PP=2)

Focus on:

- training throughput
- step time
- scaling efficiency
- GPU utilization
- VRAM usage
- communication behavior
- NCCL collectives
- pipeline bubbles
- Nsight Systems timelines

Use Megatron-LM / Megatron Core with mock data so dataset I/O is not part
of the benchmark.

Do NOT work on:

- multi-node
- RDMA / InfiniBand
- FSDP / ZeRO
- FP8
- distributed optimizer
- communication overlap optimizations
- exotic parallelism such as CP / EP

Keep the experiment simple and controlled first.

speedup = 1.0×

# 8. Experiment B — Pure DP

Configuration:

GPUs = 2
TP = 1
PP = 1

Therefore:

DP = world_size / (TP × PP)
   = 2

Conceptually:

GPU0:
full model + different data

GPU1:
full model + different data

backward
   ↓
gradient AllReduce

Keep:

global_batch_size = 64

This is the strong-scaling experiment.

Compare against the 1-GPU baseline.

Calculate:

DP speedup =
    throughput_DP2 / throughput_1GPU

DP scaling efficiency =
    throughput_DP2 /
    (2 × throughput_1GPU)

Example:

1 GPU = 100k tokens/s
DP2   = 185k tokens/s

speedup = 1.85×
efficiency = 92.5%

Expected observation:

DP should usually provide the highest aggregate throughput of the three
2-GPU strategies when the model already fits on one GPU.

# 9. Experiment C — DP Weak Scaling

Now test a different question.

Baseline:

1 GPU
global_batch = 64

DP2:

2 GPUs
global_batch = 128

Keep approximately the same amount of work per GPU.

Compare:

step_time_1GPU
vs
step_time_DP2

Ideal weak scaling:

GPU count ×2
work ×2
step time ≈ unchanged

Calculate weak-scaling efficiency.

This will later be useful when extending the experiment to multiple nodes.

# 10. Experiment D — Pure TP

Configuration:

GPUs = 2
TP = 2
PP = 1
DP = 1

Conceptually:

            one Transformer layer

        ┌──────────┴──────────┐
      GPU0                   GPU1
  part of tensor         part of tensor
        │                     │
        └──── collective ─────┘

Both GPUs cooperate on the same model replica.

Keep:

global_batch_size = 64

Initially DO NOT enable extra optimizations such as:

- sequence parallel
- async communication overlap
- FP8

The first goal is to isolate basic TP behavior.

Optional later experiment:

TP=2 + sequence parallel

as a separate run.

Measure:

- throughput
- step time
- VRAM
- GPU utilization

Important comparison:

1GPU vs TP2

This answers:

"Does using two GPUs to compute one model replica make a step faster?"

Also compare:

TP2 vs DP2

This demonstrates the difference between:

DP:
two replicas doing different work

TP:
two GPUs cooperating on one replica

Expected:

TP should show much more frequent inter-GPU communication than DP.

# 11. Experiment E — Pure PP

Configuration:

GPUs = 2
TP = 1
PP = 2
DP = 1

Conceptually:

GPU0:
layers 0 ~ 11
      ↓
activation communication

GPU1:
layers 12 ~ 23

Keep the same model and global batch.

Measure:

- tokens/s
- step time
- VRAM per GPU
- utilization

Important observation:

PP splits layers rather than tensors.

Look for:

- pipeline startup
- pipeline drain
- idle periods
- pipeline bubble

PP does NOT directly make each Transformer layer compute faster.

# 12. Experiment F — PP Microbatch Sweep

This is important.

Keep:

PP = 2
global_batch = 64

Try:

micro_batch_size = 1
micro_batch_size = 2
micro_batch_size = 4

Only use configurations that fit in VRAM.

For DP=1:

micro batch 1
→ ~64 microbatches

micro batch 2
→ ~32 microbatches

micro batch 4
→ ~16 microbatches

Compare:

- step time
- tokens/s
- GPU utilization
- peak memory

Goal:

understand the tradeoff between:

more microbatches
→ smaller pipeline bubble

versus

larger microbatch
→ potentially better GEMM efficiency
→ higher memory usage

Produce a table showing PP throughput vs microbatch size.

1. DP2
2. TP2
3. PP2

Store traces in:

profiles/

## DP

Expected pattern:

compute
   ↓

## TP

Expected pattern:

GEMM
↓
NCCL
↓
GEMM
↓
NCCL
↓
...

Communication should be much more frequent because tensors are partitioned
inside layers.

## PP

Expected pattern:

GPU0:
compute ─ compute ─ compute ...

GPU1:
        compute ─ compute ─ compute ...

Look for pipeline offset and idle bubbles.

Generate either screenshots or useful nsys textual summaries.

# 16. Questions the Final Report Must Answer

At the end, write README.md explaining the results and explicitly answer:

1. How much faster is DP=2 than one GPU?
2. What is DP scaling efficiency?
3. For the same global batch, is TP=2 faster than one GPU?
4. Is TP=2 more or less efficient than DP=2?
5. How much VRAM does TP save?
6. How much VRAM does PP save?
7. How does PP throughput change as the number of microbatches changes?
8. What do DP, TP and PP look like in an Nsight timeline?
9. Which parallelism strategy communicates most frequently?
10. Why is DP normally preferred when the model already fits on one GPU?
11. Why might TP still be useful even if the model fits on one GPU?
12. Why is PP mainly useful for larger models / larger GPU counts?
